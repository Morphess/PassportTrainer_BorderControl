# Аудит бази паспортних документів Passport Trainer

Дата аудиту: 2026-09-12  
Каталог джерела: `Зразки паспортних документів/`

## Підсумок

- У базі є **173 каталоги другого рівня**, які за наявною структурою виконують роль каталогів країн.
- Після технічної нормалізації назв (Unicode NFC, без урахування регістру та повторних пробілів) це **141 унікальна назва**.
- Число 141 не можна без ручної верифікації трактувати як кількість суверенних держав: у наборі є дубльовані й помилково розміщені каталоги, території, невизнані утворення та одна міжнародна організація.
- Знайдено **521 зображення документів** і 4 службові файли `.DS_Store`, усього 525 файлів.
- Усі 521 зображення технічно читаються. Фактичний формат кожного з них відповідає розширенню.
- За SHA-256 знайдено **87 груп точних дублікатів**: у них перебувають 177 файлів, з яких 90 є додатковими копіями. Унікальних бінарних зображень — 431.
- Країну можна синтаксично визначити зі шляху для 519 із 521 зображення. Два файли у вкладеному каталозі `Африка/бенін/бруней/` мають неоднозначну належність.
- Тип можна синтаксично визначити за назвою файла або каталогу для 520 із 521 зображення, якщо враховувати відомі скорочення та помилки. Це не гарантує, що підпис відповідає зображенню.

## 1. Загальна структура бази

Основна схема зберігання:

```text
Зразки паспортних документів/
└── <континент>/
    └── <країна або інша географічна сутність>/
        └── <тип документа>.<jpg|jpeg|png>
```

На верхньому рівні є сім каталогів:

1. `Європа`
2. `Австралія континент`
3. `Азія`
4. `Африка`
5. `Океанія`
6. `Південна Америка`
7. `Північна Амерка`

Назва `Північна Амерка` містить орфографічну помилку. Австралія та Океанія представлені як окремі континентальні групи, тому майбутня модель повинна явно зафіксувати саме цю таксономію або замінити її узгодженою канонічною схемою.

Розподіл:

| Каталог континенту | Каталогів країн | Зображень | Службових файлів |
|---|---:|---:|---:|
| `Європа` | 45 | 164 | 1 |
| `Австралія континент` | 1 | 3 | 0 |
| `Азія` | 32 | 93 | 1 |
| `Африка` | 65 | 184 | 0 |
| `Океанія` | 11 | 29 | 0 |
| `Південна Америка` | 9 | 24 | 1 |
| `Північна Амерка` | 10 | 24 | 0 |
| **Разом** | **173** | **521** | **4** |

516 зображень лежать безпосередньо на рівні `<континент>/<країна>/<файл>`. П'ять зображень мають додатковий рівень вкладеності:

- `Європа/Кіпр/ДП/165090.jpeg`;
- `Європа/Кіпр/ЗЗП/164606.jpeg`;
- `Європа/Кіпр/СП/164908.jpeg`;
- `Африка/бенін/бруней/дипломатичний.png`;
- `Африка/бенін/бруней/ззп.png`.

Перші три використовують вкладений каталог як позначення типу. Останні два утворюють структурну помилку: каталог однієї країни вкладений у каталог іншої.

## 2. Кількість країн

Результат залежить від способу підрахунку:

- **173** — фізичні каталоги на очікуваному рівні `<континент>/<країна>`;
- **142** — унікальні текстові назви каталогів без нормалізації;
- **141** — унікальні назви після NFC-нормалізації Unicode, приведення регістру та згортання повторних пробілів.

Для імпорту найбільш коректним технічним показником є **141 унікальна назва**, але це ще не 141 підтверджена країна. Наприклад:

- `група африканського банку розвитку` — організація, а не країна;
- `Макао`, `бермудські острови`, `Північний Кіпр`, `Сомаліленд` мають статус, який треба моделювати окремо від звичайної суверенної держави;
- `Корея` не уточнює державу, а `Корея Яка` виглядає як пошкоджена назва;
- `Македонія` та `Північна  Македонія` можуть означати історичні/сучасні варіанти однієї держави або різні серії документів;
- `Кіпр` присутній у Європі, Азії та Африці.

Отже, остаточну кількість канонічних країн слід визначити після створення ручної таблиці відповідності `source path -> canonical country/entity`.

## 3. Кількість документів

Під «документом» на цьому етапі рахується один файл зображення:

- **521** зображення документів;
- **431** унікальний бінарний вміст за SHA-256;
- **4** додаткові файли `.DS_Store`, які не є документами;
- загальний обсяг зображень — приблизно **94,30 MiB**.

Автоматична попередня класифікація за назвами дала:

| Попередній тип | Кількість зображень |
|---|---:|
| Звичайний/закордонний (`ззп`) | 133 |
| Дипломатичний | 162 |
| Службовий | 79 |
| Внутрішній документ / ID | 146 |
| Невідомий | 1 |
| **Разом** | **521** |

Це синтаксична, а не експертна класифікація. Вона враховує назви каталогів `ДП`, `ЗЗП`, `СП` та очевидні друкарські помилки. Виявлені конфлікти між назвою й однаковим вмістом наведено нижче.

Одна країна зазвичай містить кілька типів документів. Із 173 фізичних каталогів:

- 61 мають 4 розпізнані типи;
- 50 мають 3 типи;
- 58 мають 2 типи;
- 4 мають лише 1 тип.

Каталоги з одним типом: `Європа/бермудські острови`, `Африка/Нігерія`, `Африка/група африканського банку розвитку`, `Океанія/Палау`.

## 4. Формати

Розширення файлів:

| Розширення | Кількість | Фактичний MIME/формат |
|---|---:|---|
| `.jpg` | 434 | `image/jpeg`, JPEG |
| `.jpeg` | 3 | `image/jpeg`, JPEG |
| `.png` | 84 | `image/png`, PNG |
| `.DS_Store` | 4 | `application/octet-stream`, не зображення |

Розміри зображень неоднорідні: знайдено 347 комбінацій ширини й висоти. Найменше зображення має 205×300 пікселів, найбільше — 1031×1280 пікселів.

Перевірка ImageMagick з увімкненим обробленням попереджень успішно прочитала всі 521 зображення. Нульових файлів, невідповідностей між розширенням та сигнатурою або технічно пошкоджених зображень не виявлено. Якість та правильність кожного зображеного документа візуально не верифікувалися повністю.

## 5. Приклади структури

Типова структура з чотирма видами документів:

```text
Зразки паспортних документів/Європа/Україна/
├── ззп.jpg
├── дипломатичний.jpg
├── службовий.jpg
└── внутрішній.jpg
```

Неповний набір:

```text
Зразки паспортних документів/Океанія/Палау/
└── внутрішній.jpg
```

Варіанти одного типу:

```text
Зразки паспортних документів/Європа/нідерланди/
├── ззп.jpg
├── ЗЗП (2).jpg
├── дипломатичний.jpg
├── службовий.jpg
└── внутрішній.jpg
```

Нетипова вкладеність, де тип визначається каталогом:

```text
Зразки паспортних документів/Європа/Кіпр/
├── id.jpg
├── ДП/165090.jpeg
├── ЗЗП/164606.jpeg
└── СП/164908.jpeg
```

Некоректна або неоднозначна вкладеність:

```text
Зразки паспортних документів/Африка/бенін/
├── ззп.png
├── дипломатичний.png
└── бруней/
    ├── ззп.png
    └── дипломатичний.png
```

### Принцип іменування

Основні імена — `ззп`, `дипломатичний`, `службовий`, `внутрішній`, `id`. Реєстр, орфографія й деталізація неуніфіковані. Трапляються:

- уточнення: `внутрішній паспорт`, `внутрішній id`, `службовий паспорт`;
- додаткові варіанти: `ЗЗП (2)`, `дипломатичний 2`, `службовий 2`;
- помилки: `сллужбовий`, `внурішній`, `внутршній`, `дтпломтиний`;
- скорочення: `ДП`, `ЗЗП`, `СП`;
- непрозорі назви: `164606.jpeg`, `164908.jpeg`, `165090.jpeg`, `dyenhsiysq.jpg`.

Країна майже завжди визначається другим компонентом відносного шляху, а тип — основою імені файла. Для вкладених кіпрських файлів тип визначається назвою батьківського каталогу. Автоматичний імпортер має працювати з таблицею псевдонімів, але сумнівні записи не повинен приймати без позначки ручної перевірки.

## 6. Виявлені проблеми

### 6.1. Географічно неправильні або дубльовані каталоги

У `Африка` повторено 31 назву з `Азія`: Азербайджан, Афганістан, Бангладеш, Бруней, Бутан, В'єтнам, Вірменія, Катар, Бахрейн, Кіпр, М'янма, Макао, Малайзія, Мальдіви, Непал, ОАЕ, Оман, Пакистан, Північний Кіпр, Саудівська Аравія, Сингапур, Сирія, Таджикистан, Тайвань, Таїланд, Туреччина, Туркменістан, Узбекистан, Філіпіни, Шрі-Ланка та Ємен.

Ці 31 африканський каталог містять 83 зображення. Для 82 із них є точні копії в азійській гілці; `Африка/Мальдіви/внутрішній.jpg` точного відповідника в `Азія` не має. Додатково три зображення з `Африка/Корея` точно збігаються з файлами `Азія/Корея Яка`.

Також виявлено:

- `Південна Америка/Південна Африка` — 3 зображення;
- `Європа/бермудські острови` — 1 зображення;
- `Африка/бенін/бруней` — 2 зображення Брунею всередині Беніну;
- `Кіпр` одночасно в Європі, Азії та Африці;
- поділ `Австралія континент` / `Океанія` потребує формального рішення для моделі.

### 6.2. Точні дублікати

SHA-256 аналіз показав:

- 87 груп однакового бінарного вмісту;
- 177 файлів у цих групах;
- 90 надлишкових копій відносно одного файла на групу;
- 431 унікальне бінарне зображення.

Основна причина — копія азійського фрагмента в `Африка`. Окремі важливі випадки:

- `Європа/данія/внутрішній id.jpg` і `Європа/австрія/внутрішній id.jpg` однакові; на зображенні явно зазначено Austria, тому данський запис помилково атрибутований;
- `Африка/ангола/ДП.png` і `Африка/ангола/дтпломтиний.png` однакові;
- два файли `Африка/бенін/бруней/*` дублюють відповідні файли в каталогах Брунею;
- `Європа/Кіпр/id.jpg`, `Азія/кіпр/id.jpg` та `Африка/кіпр/id.jpg` однакові.

Хеші виявляють точні копії. Візуально однакові зображення, які були повторно стиснуті, обрізані або масштабовані, можуть мати різні хеші й потребують окремого перцептивного аналізу.

### 6.3. Конфлікти типу документа

Однакові байти підписані різними типами:

- `Азія/Оман/ззп.jpg` = `Африка/Оман/внутрішній.jpg`; зображення має напис `PASSPORT`, але остаточний тип треба підтвердити;
- `Азія/пакистан/ззп.jpg` = `Африка/пакистан/внутрішній.jpg`; зображення має напис `PASSPORT`, але остаточний тип треба підтвердити;
- `Азія/Катар/внутрішній.jpg` = `Африка/Катар/dyenhsiysq.jpg`; назва другого файла не задає тип, а саме зображення має загальний напис `PASSPORT`.

### 6.4. Неуніфіковані назви та Unicode

- 22 каталоги країн мають назви не в Unicode NFC.
- 377 назв зображень мають декомпоновані Unicode-символи.
- Є суміш верхнього й нижнього регістру назв країн та документів.
- `Північна  Македонія` містить подвійний пробіл.
- Є друкарські помилки у назвах країн: `Північна Амерка`, `Корея Яка`, `Шрі Ланк`, `ботсавата`, `аззербайджан`.
- Колізій імен усередині одного каталогу після NFC-нормалізації та приведення регістру не знайдено, але імпортер все одно має враховувати нечутливість Windows до регістру.

### 6.5. Службові файли

Не є документами та мають бути проігноровані імпортером:

- `Зразки паспортних документів/.DS_Store`;
- `Зразки паспортних документів/Європа/.DS_Store`;
- `Зразки паспортних документів/Азія/.DS_Store`;
- `Зразки паспортних документів/Південна Америка/.DS_Store`.

## 7. Файли, які потребують ручної перевірки

### Найвищий пріоритет

| Шлях або група | Причина |
|---|---|
| `Африка/Катар/dyenhsiysq.jpg` | Тип неможливо визначити з назви; точний дубль `Азія/Катар/внутрішній.jpg`, але зображено паспорт. |
| `Азія/Оман/ззп.jpg` і `Африка/Оман/внутрішній.jpg` | Однаковий вміст, конфлікт типів. |
| `Азія/пакистан/ззп.jpg` і `Африка/пакистан/внутрішній.jpg` | Однаковий вміст, конфлікт типів. |
| `Європа/данія/внутрішній id.jpg` | Точна копія австрійської ID-картки; неправильна країна. |
| `Африка/бенін/бруней/ззп.png` | Країна неоднозначна через вкладеність; вміст дублює Бруней. |
| `Африка/бенін/бруней/дипломатичний.png` | Країна неоднозначна через вкладеність; вміст дублює Бруней. |
| Усі 86 зображень в азійському блоці каталогу `Африка` | 83 зображення в 31 однойменному з Азією каталозі та 3 у `Корея`; географічна гілка хибна. |
| `Південна Америка/Південна Африка/*` | Хибний континент. |
| `Європа/бермудські острови/ззп.png` | Хибна або щонайменше неузгоджена континентальна класифікація. |

### Назви, тип яких можна припустити, але треба підтвердити

- `Європа/Кіпр/ДП/165090.jpeg` — імовірно дипломатичний;
- `Європа/Кіпр/ЗЗП/164606.jpeg` — імовірно звичайний/закордонний;
- `Європа/Кіпр/СП/164908.jpeg` — імовірно службовий;
- `Європа/греція/сллужбовий.jpg` — очевидна помилка в слові «службовий»;
- `Європа/румунія/внутршній.jpg` — очевидна помилка в слові «внутрішній»;
- `Африка/Сенегал/внурішній.jpg` — очевидна помилка в слові «внутрішній»;
- `Африка/ангола/дтпломтиний.png` — імовірно дипломатичний і точний дубль `ДП.png`;
- `Європа/нідерланди/ЗЗП (2).jpg`, `Європа/мальта/дипломатичний 2.jpg`, `Європа/мальта/службовий 2.jpg` — перевірити, чи це окремі історичні/актуальні варіанти, а не дублікати.

### Сутності, які потребують канонічного рішення

- `Корея` / `Корея Яка` — визначити конкретну державу;
- `Македонія` / `Північна  Македонія` — визначити, чи це одна країна з різними поколіннями документів;
- `Нова Гвінея` — уточнити, чи мається на увазі Папуа-Нова Гвінея;
- `група африканського банку розвитку` — класифікувати як організацію або спеціального емітента;
- `Макао`, `Північний Кіпр`, `Сомаліленд`, `бермудські острови` — задати тип геополітичної сутності;
- `Свазіленд` — зафіксувати канонічну сучасну назву та зберегти стару як псевдонім;
- `Кіпр`, `Туреччина`, `Східний Тимор` — узгодити правила віднесення трансконтинентальних/прикордонних випадків.

## 8. Запропонована модель даних

Оригінальний шлях потрібно зберігати як джерельний атрибут, але не використовувати як первинний ключ або єдине джерело істини.

### `Continent`

| Поле | Призначення |
|---|---|
| `id` | Стабільний внутрішній ідентифікатор. |
| `code` | Машинний код, наприклад `EUROPE`, `ASIA`. |
| `displayNameUk` | Українська назва для інтерфейсу. |
| `sourceName` | Початкова назва каталогу. |
| `sortOrder` | Порядок відображення на карті/у списках. |

### `Country`

| Поле | Призначення |
|---|---|
| `id` | Стабільний внутрішній ідентифікатор. |
| `canonicalNameUk` | Канонічна українська назва. |
| `normalizedName` | NFC-нормалізований ключ пошуку. |
| `isoAlpha2`, `isoAlpha3` | ISO-коди, nullable для територій/організацій. |
| `entityType` | `SOVEREIGN_STATE`, `TERRITORY`, `DISPUTED_ENTITY`, `ORGANIZATION`, `UNKNOWN`. |
| `primaryContinentId` | Основний континент для навігації. |
| `sourceName` | Початкова назва каталогу без її зміни на диску. |
| `reviewStatus` | `VERIFIED`, `AUTO_CLASSIFIED`, `NEEDS_REVIEW`, `REJECTED`. |

Якщо країна може бути показана на кількох континентах, між `Country` і `Continent` доцільний зв'язок many-to-many через технічну таблицю `country_continent`, а `primaryContinentId` залишити для основного маршруту гри.

### `DocumentType`

| Поле | Призначення |
|---|---|
| `id` | Ідентифікатор довідника. |
| `code` | `ORDINARY_PASSPORT`, `DIPLOMATIC_PASSPORT`, `SERVICE_PASSPORT`, `NATIONAL_ID`, `UNKNOWN`. |
| `displayNameUk` | Назва для інтерфейсу. |
| `description` | Навчальний опис типу. |

Псевдоніми на кшталт `ззп`, `ДП`, `СП`, `id` і відомі помилкові написання мають бути окремою конфігурацією імпортера, а не додатковими значеннями `DocumentType`.

Починаючи зі Stage 4C, цей набір кодів є authoritative `DocumentType` contract у Java-коді й документації. Dataset не підтверджує окремі canonical типи `TEMPORARY` або `OTHER`; неоднозначні записи мають залишатися `UNKNOWN` до ручної перевірки. Це рішення не змінює вихідні назви файлів і каталогів.

### `PassportDocument`

| Поле | Призначення |
|---|---|
| `id` | Ідентифікатор логічного документа/варіанта. |
| `countryId` | Емітент. |
| `documentTypeId` | Тип документа. |
| `title` | Людська назва варіанта. |
| `variant` | Серія, покоління або номер варіанта, якщо відомо. |
| `validFrom`, `validTo` | Період застосування, nullable. |
| `isCurrent` | Ознака актуальності, nullable до перевірки. |
| `sourceRelativePath` | Початковий відносний шлях для трасування. |
| `reviewStatus` | Статус ручної перевірки. |
| `notes` | Пояснення неоднозначностей. |

Один `PassportDocument` може мати кілька `PassportImage`: обкладинка, сторінки, альтернативні ракурси або якісніші копії. Два файли не слід автоматично об'єднувати в один документ лише через однаковий тип.

### `PassportImage`

| Поле | Призначення |
|---|---|
| `id` | Ідентифікатор зображення. |
| `documentId` | Посилання на логічний документ. |
| `relativePath` | Платформонезалежний відносний шлях до ресурсу. |
| `originalFileName` | Початкове ім'я файла. |
| `mimeType`, `format` | `image/jpeg`/`JPEG` або `image/png`/`PNG`. |
| `width`, `height`, `fileSize` | Технічні метадані. |
| `sha256` | Контроль цілісності та пошук точних дублікатів. |
| `sortOrder` | Порядок показу. |
| `reviewStatus` | Статус перевірки конкретного зображення. |

Зв'язки:

```text
Continent 1 ── N Country
Country 1 ── N PassportDocument
DocumentType 1 ── N PassportDocument
PassportDocument 1 ── N PassportImage
```

Для трансконтинентальної моделі перший зв'язок замінюється на `Continent N ── M Country`.

## 9. Рекомендації щодо інтеграції з Java

1. **Залишити джерело незмінним.** Майбутній імпортер повинен читати `Зразки паспортних документів/` у режимі read-only та створювати окремий SQLite-каталог/manifest.
2. **Відокремити фізичне ім'я від канонічних даних.** Виправлену країну, континент і тип зберігати в SQLite; оригінальний відносний шлях — окремо для аудиту.
3. **Не зберігати великі зображення у SQLite BLOB без потреби.** Для локального desktop-застосунку практичніше пакувати read-only каталог ресурсів, а в SQLite зберігати відносні шляхи, метадані та SHA-256.
4. **Створити керований manifest імпорту.** Він має містити канонічну країну, тип, джерельний шлях, хеш і `reviewStatus`; сумнівні записи не повинні автоматично потрапляти до навчальних чи екзаменаційних завдань.
5. **Нормалізувати лише логічні значення.** У Java застосовувати `Normalizer.normalize(value, Normalizer.Form.NFC)`, `Locale.ROOT`, обрізання та згортання пробілів. Файли на диску не перейменовувати.
6. **Використовувати `java.nio.file.Path`.** Не формувати шляхи через `/` або `\\`; зберігати в БД відносні URI-подібні шляхи й перетворювати їх через `Path` під час завантаження.
7. **Урахувати Windows.** Перевіряти можливі колізії після NFC-нормалізації та приведення регістру, довжину шляхів і доступність UTF-8 назв. Поточних case/NFC-колізій усередині одного каталогу не знайдено.
8. **Не робити `sha256` унікальним ключем.** Однакове зображення може навмисно мати кілька джерельних посилань; хеш слід індексувати для пошуку дублікатів, а об'єднувати записи тільки після перевірки.
9. **Розділити каталог і прогрес користувача.** Пакований каталог документів має бути read-only; SQLite з користувачами, ролями, результатами та налаштуваннями — у `%LOCALAPPDATA%/PassportTrainer` на Windows.
10. **Перед імпортом затвердити таблицю ручних виправлень.** Найперше виправити логічне відображення азійського блоку в `Африка`, Південної Африки, Бермудів, Данії/Австрії та трьох конфліктів типів. Оригінальні файли при цьому не змінювати.

## Методика та межі аудиту

- Рекурсивно проаналізовано всі каталоги й файли.
- Формат перевірено за розширенням, MIME-сигнатурою та декодуванням ImageMagick.
- Точні дублікати визначено за SHA-256 усього файла.
- Unicode-перевірка виконана з NFC-нормалізацією.
- Семантично конфліктні зображення переглянуто вибірково.
- Повна експертна перевірка справжності, країни, покоління та актуальності кожного документа не виконувалась; для цього потрібен окремий ручний етап.

## 10. Stage 5 canonical manifest

Stage 5 повторив аудит напряму з filesystem і підтвердив основні кількісні висновки: 7 continent directories, 173 second-level entity directories, 521 readable images, 4 service files, 431 SHA-256 groups, 87 exact-duplicate groups і 90 додаткових copies. Уточнення: 22 second-level entity directories не NFC, а recursive count дорівнює 23 через додатковий nested directory `Африка/бенін/бруней`.

Versioned hand-maintained inputs розташовані в `data/passport-metadata/`:

- `continents.tsv` — physical-to-canonical continent mapping;
- `entity-corrections.tsv` — aliases, canonical names, entity types, geography, review decisions and notes;
- `document-type-aliases.tsv` — filename/directory tokens mapped only to the Stage 4C `DocumentType` contract;
- `source-overrides.tsv` — exact-path corrections without source mutation;
- `source-exclusions.tsv` — explicit non-image exclusions.

`PassportManifestGenerator` читає ці inputs разом з immutable source collection і відтворює `data/passport-manifest/`. Catalogue складається з `manifest.tsv`, `continents.tsv`, `entities.tsv`, `documents.tsv`, `images.tsv` та `aliases.tsv`. TSV обрано замість JSON/YAML, CSV і generated Java: normalized relational tables не потребують runtime parser dependency, дають стабільні Unicode Git diffs і прямо відповідають майбутнім SQLite tables.

Generation and standalone validation commands після compilation:

```bash
./mvnw -q -DskipTests compile
$JAVA_HOME/bin/java -cp target/classes ua.passporttrainer.manifest.PassportManifestTool generate \
  'Зразки паспортних документів' data/passport-metadata data/passport-manifest
$JAVA_HOME/bin/java -cp target/classes ua.passporttrainer.manifest.PassportManifestTool validate \
  'Зразки паспортних документів' data/passport-manifest
```

Generated manifest містить 7 continents, 139 canonical entities, 521 provisional documents, 521 source images and 166 aliases. Document types: 133 `ORDINARY_PASSPORT`, 162 `DIPLOMATIC_PASSPORT`, 79 `SERVICE_PASSPORT`, 146 `NATIONAL_ID`, 1 `UNKNOWN`. Review state: 462 documents `AUTO_CLASSIFIED`, 59 `NEEDS_REVIEW`; verified documents наразі відсутні, тому всі 521 records мають `quizEligible=false`.

Stable text IDs використовують full SHA-256: entity ID походить від versioned canonical normalized key, document/image IDs — від NFC-normalized POSIX source-relative path. Absolute installation path, host separator і filesystem order не впливають на identity. Exact SHA-256 copies не зливаються: кожен source file має окремі document/image IDs, а 90 additional copies посилаються через `duplicateOfDocumentId` і `duplicateOfImageId` на lexicographically first NFC/POSIX source path.

Validator перевіряє unique IDs, complete source-image coverage, існування/size/SHA-256 source files, canonical enum/status values, continent/entity/document/image references, deterministic IDs and ordering, duplicate representatives, summary counts, aliases та quiz eligibility. `UNKNOWN`, unresolved entity/type/geography conflicts і conflicting duplicate groups не можуть потрапити до quiz pool.

Manifest підтримує primary і alternate continent IDs, але наявний `Country` domain record має лише один `continentId`. До SQLite integration потрібне окреме рішення: зберегти primary continent для основного маршруту та додати many-to-many relation для Cyprus, Turkey, Timor-Leste і майбутніх transcontinental cases. Stage 5 не змінює `Country`, не створює SQLite schema і не інтегрує catalogue в application UI.

## 11. Stage 6 SQLite catalogue

Stage 6 не повторює filesystem audit. `PassportCatalogueImporter` читає лише canonical Stage 5 manifest після source-independent contract validation. Metadata corrections уже materialized у manifest; importer не має filename/directory classification logic і не змінює ні source assets, ні TSV.

Schema version 1 зберігає stable manifest IDs як `TEXT PRIMARY KEY`. Primary та alternate geography нормалізовано в `entity_continents`; original entity names — в `entity_source_names`; exact source-relative POSIX paths — у `passport_images`. `documents` і `passport_images` зберігають review status та self-referencing duplicate links, а `documents` окремо зберігає `quiz_eligible`.

Full import дає 7 `continents`, 139 `entities`, 521 `documents`, 521 `passport_images`, 166 `aliases` і 142 `entity_continents` rows: 139 primary та 3 alternate. DocumentType counts залишаються 133/162/79/146/1; review state — 462 `AUTO_CLASSIFIED` і 59 `NEEDS_REVIEW`; quiz-eligible rows — 0; duplicate document/image references — по 90.

Schema відтворюється plain SQL migration `V001__create_catalogue.sql`; lightweight runner зберігає SHA-256 migration checksum. Import виконується transactionally із foreign keys enabled, post-import integrity validation та rollback on failure. Repeatability порівнюється SHA-256 ordered logical rows, а не raw SQLite bytes, бо page layout не є catalogue contract.

Packaged reference catalogue має відкриватися read-only. Future writable users/settings/results/statistics database залишається окремою та повинна бути розміщена в `%LOCALAPPDATA%\\PassportTrainer` на Windows, а не в application installation directory.
